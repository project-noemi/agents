## [2026-07-03-0001] Branching Invariant — `develop` Is the Only Valid PR Source Into `main`

- **Decision:** The canonical flow is `feature/* → develop → main`. `develop` MUST contain everything on `main` at all times; the **only** valid PR source into `main` is `develop`. The `require-develop-source` CI gate (`.github/workflows/require-develop-source.yml`) is narrowed to enforce exactly this — all pre-existing wildcard exceptions (`doc-workflow-audit-drift*`, `doc-requirements-refinement*`, `doc-requirements-drift-audit*`, `doc-reality-check*`, `doc-requirements-update*`, `doc-requirements-uplift*`) are removed. Doc-uplift and other automation must open PRs into `develop` and reach `main` only via a `develop → main` release PR. If a genuine hotfix-to-main path is ever required, it must be added as a single explicit, documented exception — never a broad `doc-*` wildcard.
- **Context:** Doc-uplift automation (e.g. PRs #250, #252) had been merging **directly into `main`** through the gate's accreted wildcard whitelist (added piecemeal in prior "fix CI whitelist" commits). This repeatedly diverged `main` from `develop`: `main` gained commits `develop` lacked, which put the in-flight release PR #248 (`develop → main`) into merge conflict on `docs/REQUIREMENTS.md` and forced a manual sync-down (PR #255, `main → develop`) before the release could proceed. Standard Git-flow treats the trunk as strictly downstream of the integration branch; every direct-to-trunk merge breaks that invariant and taxes the next release with a reconciliation. Removing the wildcards makes the invariant self-enforcing rather than relying on remembering to sync down.
- **Impact:** `.github/workflows/require-develop-source.yml` now allows only `develop` as a PR head into `main`, with an explanatory failure message pointing at this decision and `CONTRIBUTING.md#branching-model`. Automation that previously targeted `main` directly must be repointed at `develop` (its PRs to `main` will now fail the gate by design). Eliminates the recurring divergence-then-sync-down cycle observed across the #248/#250/#252/#255 sequence.

## [2026-08-20-0003] Automation Takes No Action On a Human's Draft; Only the Machine Identity's Own Drafts Are Touched

- **Decision:** The PR merge gate (Decision [2026-08-17-0002]) treats a draft pull request the machine identity did not author as entirely out of scope: it returns the new terminal verdict `DRAFT_HELD` and performs **none** of its actions — no close/reopen to re-fire a review, no remediation order to push commits, no public escalation issue, and no marking the draft ready. Draft is the author's "not ready" declaration, and it outranks a passing verdict and green checks. The machine identity's own drafts are process artifacts and continue through every branch as before (the scheduled Doc run opens its PRs as drafts, but those drafts are bot-authored only while the machine token is injected — see the operational consequence below). Authorship is verified against BOTH the pinned login `noemi-agent` and the immutable numeric user id `311935378` (docs/MACHINE_IDENTITY.md); a mismatch on either fails closed to `DRAFT_HELD`, and `Number.isInteger` is applied to the raw payload value so string look-alikes cannot decide identity. The check is duplicated at the mutation site (`armAutoMerge` throws rather than readying a foreign draft) because that function is exported and the guarantee must hold for any caller, not only one that consults the verdict first.
- **The pin is deliberately NOT configurable.** Reading the identity from `AGENT_GH_EXPECTED_LOGIN` plus a new `AGENT_GH_EXPECTED_ID` was considered and rejected: the existing variable already means "which account must this *token* resolve to" and this repository documents setting it to `noemi-reviewer` for reviewer flows (docs/MACHINE_IDENTITY.md, docs/examples/cross-model-review-setup.md), so a reviewer-configured session would have silently retargeted — or, with a mismatched id, wholly disabled — the draft rule; and an environment variable that widens who may override a human's signal is a privilege switch, not configuration. Changing the identity is now a reviewed code change alongside the register, pinned by a test that reads `docs/MACHINE_IDENTITY.md`. An invocation flag (`--ready-drafts`) drafted in the same remediation was discarded for the same reason: a caller promise is not a verifiable property of the pull request.
- **Context:** Arming auto-merge on a draft fails at the API ("Pull request is a draft"), hit live while finalizing PR #435. The first fix readied any draft that reached `ARMED_AUTOMERGE`, which cross-model review flagged as a high code finding: pointing the gate at a human's work in progress would pull it out of draft the moment its checks went green. The owner's remediation directive was explicit — "make sure the draft to reviewable rule only applies to bot created PR, not PRs humans are working on." A four-lens adversarial verification of that first remediation then found the guard was placed last in `decideVerdict`, protecting only the un-drafting step while leaving the reopen, remediation-order and escalation branches free to act on a foreign draft; the guard now sits with the PR-state checks, where "hands off entirely" is expressible.
- **Impact:** `scripts/pr-merge-gate.js` gains `isAgentAuthored()`, the `DRAFT_HELD` terminal verdict (emitted on stdout with the standard audit log on stderr, whose `risks` name the indefinite wait, so a held PR is never a silent no-op) and the mutation-site refusal. `docs/DEV_AGENT_PROMPT.md` gains the verdict's row in the scheduled-agent action table, including the instruction not to self-ready. Tests cover the pure verdict across all four intrusive branches, the impostor matrix, the register pin, the mutation-site refusal, and the previously untested `collectState` wiring that derives `draft`/`agentAuthored` from the REST payload. **Residual risk (accepted, documented):** the check keys on who *opened* the PR, not who set the draft flag, so if a human converts a bot-authored PR to draft as a stop signal the gate will still treat it as its own; detecting that requires a timeline scan for `convert_to_draft` actors and is deferred rather than hidden. **Operational consequence** while the `AGENT_GH_TOKEN` injection gap persists (Clarification [2026-08-09]): scheduled Doc-run PRs are authored by the session owner's human account and open as drafts, so they now return `DRAFT_HELD` and wait for a human to mark them ready — the identity gap surfaces rather than being papered over by automation.
